## Project Overview

IdeaNest is a full-stack idea-management application. It has two top-level workspaces:

- `api/` — NestJS 11 backend (TypeScript, NodeNext, Express adapter)
- `web/` — React 19 + Vite 8 frontend (TypeScript, Tailwind v4, shadcn/ui, Redux Toolkit)

They run independently. Both must be running for end-to-end use (web dev port 5173, api default port 3000 — CORS is already pinned to `http://localhost:5173` in `api/src/main.ts`).

## Common Commands

All commands are run from the respective workspace root (`api/` or `web/`).

### API (`api/`)

- `npm run start:dev` — Nest dev server with watch reload (port 3000)
- `npm run build` — Compile to `dist/` via `nest build`
- `npm run start:prod` — Run the compiled `dist/main.js`
- `npm run lint` — ESLint (flat config) over `src/`, `test/`
- `npm run format` — Prettier write
- `npm test` — Jest unit tests (rootDir: `src`, matches `*.spec.ts`)
- `npm run test:watch` — Jest watch mode
- `npm run test:cov` — Jest with coverage (output to `../coverage`)
- `npm run test:e2e` — e2e suite (config: `test/jest-e2e.json`)
- `npm run db:generate` — drizzle-kit generate SQL migrations from `src/db/schema/index.ts`
- `npm run db:push` — drizzle-kit push schema directly (dev)
- `npm run db:migrate` — drizzle-kit apply migrations
- `npm run db:studio` — drizzle-kit studio (DB GUI)

To run a single unit test file: `npx jest path/to/file.spec.ts`.

### Web (`web/`)

- `npm run dev` — Vite dev server (port 5173, by default proxies not configured — see `VITE_API_URL`)
- `npm run build` — `tsc -b` (project references) + `vite build`
- `npm run preview` — Preview the production build
- `npm run lint` — ESLint flat config

The web `package.json` has no `test` script. Linting + `tsc -b` are the only static checks.

## Environment

`api/.env` is required (already populated locally, but values are committed and should be rotated if published):

- `DATABASE_URL` — Neon Postgres connection string (pooled, `?sslmode=require`)
- `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL` — Better Auth server secret + base URL
- `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` — Google OAuth provider

`web` reads `VITE_API_URL` for the Better Auth client base URL; falls back to `http://localhost:3000`.

## Architecture

### Backend (`api/src`)

Modular NestJS layout. Each feature owns its module, controller, service, DTOs, mappers, and (where applicable) schema/model.

- `main.ts` — Bootstraps Nest, enables CORS for `http://localhost:5173` with credentials, listens on `process.env.PORT ?? 3000`.
- `app.module.ts` — Wires `AuthModule`, `IdeaModule`, and the unused boilerplate `AppController`/`AppService`.
- `db/` — Single Drizzle instance (`drizzle({ client: pool, schema })`) re-exported as `db` and `schema`. `db/schema/index.ts` is the barrel `drizzle-kit` reads; it re-exports `auth-schema.ts` (auto-generated by `npx @better-auth/cli generate` after changing auth options) and `idea-schema.ts`.
- `auth/` — Better Auth integration. Split deliberately so the option object (`auth.config.ts`) has no DB dependency, and the runtime `auth.ts` is the only file that imports the Drizzle adapter. `auth.controller.ts` mounts `auth.handler` at `api/auth/*` by reconstructing a WHATWG `Request` from the Express `req` and forwarding the response. `auth.guard.ts` is a `@nestjs/passport`-free `CanActivate` that calls `auth.api.getSession({ headers })`; `CurrentUser` / `CurrentSession` param decorators read `request.user` / `request.session`. To make a route optional, set `Reflect.metadata("auth:optional", …)` on the handler.
- `idea/` — Reference feature: standard Nest layout with `idea.controller.ts`, `idea.service.ts`, `idea.module.ts`, plus `dto/`, `model/`, and `mapper/`. The mapper (`IdeaMapper`) is the single place that converts between DTO ⇄ domain model ⇄ Drizzle row, so controllers stay free of DB concerns and services stay free of HTTP DTO shapes. Status enum lives in `model/idea-status.model.ts` and the matching Postgres enum is in `db/schema/idea-schema.ts` (note the typo `ARCHEIVED` in the enum value — the API DTO message string mirrors this; only the web client's `IdeaStatus` type uses the correct spelling `ARCHIVED`).
- Drizzle migrations live in `drizzle/` (SQL + `meta/`). `db:generate` after schema changes; `db:migrate` to apply; `db:push` skips files for fast local iteration.

Auth flow: Better Auth handles sign-up/sign-in/session/refresh natively at `/api/auth/*`. The Nest controllers in `idea/` re-call `auth.api.getSession({ headers: req.headers })` per request to identify the current user instead of using `AuthGuard` (the guard exists for future routes). All idea operations are scoped by `session.user.id`.

### Frontend (`web/src`)

Feature-sliced structure mirroring the backend. `tsconfig` paths set `@/*` → `src/*`, used everywhere in import paths.

- `main.tsx` — Mounts `<Provider store>` + `<RouterProvider router>`. `StrictMode` is on.
- `app/` — App-wide wiring: `store.ts` (Redux Toolkit configureStore, combines `auth`, `ideas`, and `ideaApi` RTK Query slice with its middleware) and `router.tsx` (the only route table — update both data and routing here).
- `layouts/` — `RootLayout` (global shell, mounts `Toaster`) and `DashboardLayout` (auth-gated, reads `useSession()` from Better Auth's React client, redirects to `/login` if absent, syncs the session into the `auth` Redux slice).
- `lib/` — `auth.ts` (Better Auth `createAuthClient`, exposes `signIn` / `signOut` / `useSession`) and `utils.ts` (the standard shadcn `cn()` helper).
- `features/` — Domain state. `auth/authSlice.ts` is plain Redux state for the signed-in user. `ideas/ideaSlice.ts` currently carries a hard-coded `mockIdeas` array plus reducers (`addIdea`, `updateIdea`, `deleteIdea`, `setSearchTerm`, `setStatusFilter`, `setSelectedIdeaId`); the live RTK Query slice `ideas/ideaApi.ts` is scaffolded with `tagTypes: ['Idea']` but its endpoints are empty (see TODO comment) — wire endpoints there when the API client replaces the mock.
- `components/` — Three buckets: `ui/` (shadcn primitives: `button`, `card`, `dialog`, `dropdown-menu`, `input`, `textarea`, `badge`, `sonner`, plus the custom `LineWaves.tsx`), `layout/` (`Sidebar`, `Navbar`), and `ideas/` (`IdeaCard`, `IdeaGrid`, `IdeaStatusBadge`, `CreateIdeaDialog`).
- `pages/` — `Landing.tsx` (public marketing page), `auth/Login.tsx`, and `dashboard/{Dashboard,Ideas,IdeaDetails,Settings}.tsx` (gated).
- `index.css` — Tailwind v4 entry, the design-token CSS variables for the dark/neutral premium theme (`#030303` background, Geist font, shadcn `radix-nova` style), plus the `marquee-*` keyframes and `.glass-card` / `.bg-radial-accent` utilities used across the dashboard.
- Vite config (`vite.config.ts`) sets the `@` alias and the Tailwind v4 plugin. Path aliases must stay in sync between `vite.config.ts` and `tsconfig.app.json`.

### Cross-cutting conventions

- TypeScript path alias `@/*` (web) and project references via `tsconfig.json` are required for the build to succeed.
- `noUncheckedIndexedAccess` and `noUnusedLocals` are strict in both `api/tsconfig.json` and `web/tsconfig.app.json` — handle possibly-undefined array/object accesses.
- The backend relies on the Drizzle adapter to map Better Auth's table names (`user`, `session`, `account`, `verification`); don't rename these without rerunning the Better Auth CLI generator and updating `drizzle/migrations`.
- Shared env (DB + Better Auth secret) is read only on the server. The web only reads `VITE_API_URL`. Never expose `BETTER_AUTH_SECRET` to the bundle.
